# 用語集

このリポジトリで出てくる言葉を、ざっくり説明します。全部を覚える必要はありません。分からない言葉が出てきたら、ここを見てください。

## ROS 2

| 言葉 | 意味 |
|---|---|
| **ROS 2** | ロボットのプログラムを作るための仕組み。プログラムを小さな部品(ノード)に分けて、部品どうしがデータをやり取りする。このリポジトリでは **Jazzy** という版を使う |
| **ノード** | ROS 2 のプログラム 1 つ。例:`swerve_node`(足回りの計算)、`stm_bridge`(STM32 との通信) |
| **トピック** | ノードどうしがデータを流す「通り道」。名前で区別する。例:`/cmd_vel`、`/odom` |
| **メッセージ** | トピックに流すデータの形。例:`geometry_msgs/Twist`(速度)、`std_msgs/Float32MultiArray`(小数の並び) |
| **publish / subscribe** | トピックにデータを出す(publish)/ 受け取る(subscribe) |
| **パラメータ** | ノードの設定値。`config/*.yaml` に書いておき、起動するときに読み込む |
| **launch(起動ファイル)** | 複数のノードをまとめて起動するファイル。`launch/*.launch.py` |
| **パッケージ** | ノードや設定をまとめたフォルダ。`ros2_ws/src/` の下の 1 つ 1 つ |
| **ワークスペース** | パッケージをまとめて置く場所。このリポジトリでは `ros2_ws/` |
| **colcon build** | ワークスペースのパッケージをビルドするコマンド。新しいノードを足したら必要 |
| **`source install/setup.bash`** | ビルドしたパッケージを、そのターミナルで使えるようにするコマンド |
| **rviz2** | ロボットの位置やセンサーの値を、3D で表示するツール |
| **TF** | 座標(「ロボットの中心は地図のどこか」など)の関係を扱う仕組み |
| **`/diagnostics`** | 各ノードが「OK / 注意 / エラー」を知らせるための共通のトピック。ロボットコンソールの「状態」に表示される |
| **ROS_DOMAIN_ID** | 同じネットワークにいる ROS 2 を区別する番号。PC と Pi で同じ番号にすると通信でき、ほかのチームとは混ざらない |

## このリポジトリの足回り

| 言葉 | 意味 |
|---|---|
| **`/cmd_vel`** | 「この速さで走って」という指令のトピック。前後 [m/s]、左右 [m/s]、回転 [rad/s] の 3 つ。キーボード・ゲームパッド・自動操縦は、全部これを出す |
| **`/odom`(オドメトリ)** | タイヤの回転から計算した「どれだけ動いたか」(位置と速さ)。走るほど少しずつずれる |
| **スワーブ(独立ステアリング)** | タイヤごとに向きを変えられる足回り。全方向に動ける |
| **差動式(同軸差動ギア)** | 2 つのモーターで 1 つのモジュールを動かす方式。同じ向きに回すとモジュールが回り、逆向きに回すとタイヤが転がる |
| **オムニホイール** | 横には自由に滑るタイヤ。3 輪か 4 輪で全方向に動ける |
| **モジュール** | スワーブのタイヤ 1 個分の機構(タイヤ、向きを変える部分、モーター 2 個) |
| **ロボットコンソール** | 操縦・速さ・状態・停止ボタンを 1 つにまとめた PC の画面(`robot_console`) |
| **シミュレーション** | 実機の代わりに、計算でモーターの動きを真似して試すこと(`./sim.sh`) |
| **rad、rad/s** | 角度の単位(ラジアン)。1 回転 = 2π rad ≒ 6.28 rad。rad/s は 1 秒に何 rad 回るか |

## STM32 と制御

| 言葉 | 意味 |
|---|---|
| **STM32 / Nucleo-F303K8** | モーターを制御する小さなコンピューター(マイコン)。Nucleo はその開発用の基板 |
| **ファームウェア** | STM32 で動くプログラム。`firmware/` にある(C 言語) |
| **書き込み(flash)** | ビルドしたファームウェアを STM32 に入れること。`make ... flash` |
| **HAL** | ST(STM32 のメーカー)が出している、STM32 を動かすための部品集 |
| **CAN** | 複数の基板を 2 本の線でつなぐ通信の方式。車でも使われている |
| **USB シリアル** | USB ケーブルで文字のデータをやり取りする方式。Nucleo なら USB 1 本で通信できる |
| **エンコーダ** | 軸が回った量を測るセンサー。回るたびに「カチッ」と信号(パルス)を出す |
| **PPR** | エンコーダが 1 回転で出すパルスの数 |
| **カウント数** | 軸 1 回転で STM32 が数える数。**PPR × 4 × 減速比**(4 は A 相・B 相の上がり下がりを全部数えるため) |
| **減速比** | ギアでどれだけ遅くしているか。1:50 なら、モーターが 50 回転して軸が 1 回転 |
| **PWM / デューティ比** | モーターの強さを、電気を ON / OFF する割合で決める方法。デューティ比 1.0 で全力、0 で止まる |
| **PID** | 目標の速さと実際の速さのずれから、モーターの強さを決める方法 |
| **ゲイン** | PID で「ずれに対してどれくらい強く反応するか」の数字。`APP_KP` などの名前で `app_config.h` にある |
| **NODE_ID** | STM32 の基板の番号(1〜4 など)。`stm1/command` の「1」がこれ |

## Docker

| 言葉 | 意味 |
|---|---|
| **Docker** | 開発環境を「箱」に入れて、誰の PC でも同じに動かす仕組み |
| **イメージ** | 箱の設計図から作った「元」。`docker compose build dev` で作る |
| **コンテナ** | イメージから起動した「動いている箱」。`ros_dev` という名前。`ros` で中に入る |
| **Dockerfile** | イメージの作り方を書いたファイル。`docker/Dockerfile`(PC 用)、`docker/Dockerfile.pi`(Pi 用) |
| **compose.yaml** | どのコンテナをどう起動するかの設定 |
| **マウント** | PC のフォルダを、コンテナの中からも見えるようにすること。`ros2_ws/` と `firmware/` は PC とコンテナで同じフォルダ |
| **ホスト** | コンテナの外の PC のこと(表示が `名前@pc名:~$`)。コンテナの中は `root@...#` |

## Git / GitHub

| 言葉 | 意味 |
|---|---|
| **リポジトリ** | プログラムとその変更の履歴をまとめたもの。GitHub に置いてある |
| **commit** | 変更を 1 つの区切りとして記録すること |
| **push / pull** | 自分の記録を GitHub に送る / GitHub の最新を取ってくる |
| **ブランチ** | 作業の枝分かれ。`main` が本番。作業は別のブランチでやる |
| **PR(プルリクエスト)** | 「このブランチの変更を main に入れてください」というお願い。CI の結果やレビューを確認してから入れる(マージ) |
| **CI** | push のたびに GitHub で自動で動くテスト。`.github/workflows/` に設定がある |
